# Лабораторная работа 7 (доп. задание). Локальные оптимизации

**Вариант КР/РГР:** целочисленные константы (раздел 2.5 методички)  
**Конструкция:** `const MARKS: i32 = 100;`  
**Реализация:** `ir_codegen.py`, `ir_optimize.py`, `ir_pipeline.py`, вкладка GUI **«IR и оптимизации»**

---

## 1. AST и исходный IR

**Исходный код:**
```text
const MARKS: i32 = 100;
```

**AST:**
```text
Program
└── ConstDeclNode
    ├── name: "MARKS"
    ├── modifiers: ['const']
    ├── type: TypeNode → "i32"
    └── value: IntegerLiteralNode → 100
```

**Исходный IR (TAC), до оптимизаций:**
```text
  1  t0 = 100
  2  MARKS = t0
  3  type(MARKS) = i32
```

---

## 2. Описание локальных оптимизаций

Оптимизации **локальные**: применяются только внутри одного объявления `const`, без анализа остальной программы. Семантика сохраняется: имя, тип и значение константы не меняются.

| № | Название | Файл / функция | Аналог в LLVM (из методички) |
|---|----------|----------------|------------------------------|
| 1 | Устранение временной переменной (copy propagation) | `ir_optimize.py` → `optimize_eliminate_temp_copy()` | упрощение цепочки load/store, `-instcombine` |
| 2 | Свёртка констант и канонизация объявления | `ir_optimize.py` → `optimize_fold_and_canonical()` | `-constprop`, приведение к каноническому виду |

---

## 3. Таблица оптимизаций (по образцу методички, стр. 28–29)

| Оптимизация | Исходный IR | Преобразованный IR | Пояснение |
|-------------|-------------|--------------------|-----------|
| **Устранение временной переменной** | `t0 = 100`<br>`MARKS = t0`<br>`type(MARKS) = i32` | `MARKS = 100`<br>`type(MARKS) = i32` | Временная `t0` используется один раз; цепочка «загрузка константы → копирование» заменяется прямым присваиванием литерала имени. |
| **Свёртка констант и канонизация** | `MARKS = 100`<br>`type(MARKS) = i32` | `CONST MARKS : i32 = 100` | Значение `100` уже известно на этапе компиляции; две инструкции объединяются в одну каноническую форму объявления. |

**Каноническая строка (результат):**
```text
const MARKS : i32 = 100;
```

## 4. Демонстрация: входной и выходной IR

### Пример: `const MARKS: i32 = 100;`

| Этап | IR |
|------|-----|
| Вход (после `generate_tac`) | `t0 = 100` → `MARKS = t0` → `type(MARKS) = i32` |
| После оптимизации 1 | `MARKS = 100` → `type(MARKS) = i32` |
| После оптимизации 2 | `CONST MARKS : i32 = 100` |

*Скриншот для отчёта:* вкладка **«IR и оптимизации»** после **F5** на строке `const MARKS: i32 = 100;`.

## 6. Цепочка в программе (F5)

```text
const MARKS: i32 = 100;   ← редактор (исходник, не TAC)
        ↓
Лексика → Синтаксис → Семантика → valid_ast
        ↓
generate_tac()              → исходный IR (3 инструкции)
        ↓
optimize_eliminate_temp_copy()   → оптимизация 1
        ↓
optimize_fold_and_canonical()    → оптимизация 2
        ↓
Вкладка «IR и оптимизации»
```

---

## 7. Выводы

1. Для объявления целочисленной константы построены **AST** и **TAC**; IR отражает пошаговую инициализацию (литерал → имя → тип).
2. **Оптимизация 1** убирает избыточную временную переменную — аналог упрощения цепочки присваиваний в LLVM (`-instcombine`, упрощение store/load).
3. **Оптимизация 2** выполняет **свёртку константы** (значение известно при компиляции) и **канонизацию** — одна инструкция `CONST`, как подстановка константы в `-constprop`.
4. Обе оптимизации **локальны** и **сохраняют семантику** `const MARKS: i32 = 100;`.
